# Design decisions

Short log, newest first.

| Date | Decision | Why |
| --- | --- | --- |
| 2026-11-21 | **Threshold = highest validation precision with recall ≥ 0.85** instead of maximising F1/F2 | With faults as the majority class (~62%), F-beta tuning pushed every model to "always faulty" (threshold ≈ 0.1), matching the Dummy baseline. A recall floor states the real requirement (don't miss faults) and keeps false alarms down. |
| 2026-11-21 | **Serve whichever model wins on validation ROC-AUC**, and report balanced accuracy and MCC (PyTorch wins on the Kaggle data: test AUC 0.701) | On the real data (63% faults), "always faulty" scores F1 0.773, higher than any real model, so F1 can't separate a useful model from a useless one. ROC-AUC doesn't depend on the threshold; balanced accuracy and MCC are 0.5 and 0 for the dummy. All four models land within 0.005 AUC of each other, which shows the dataset is the ceiling. The scikit-learn model is saved (compressed) only when it is the one served. |
| 2026-11-21 | **Occlusion attribution for "readings that drove this result"** (reset one sensor to its healthy mean, re-score) | The first version ranked sensors by z-score distance from healthy, which showed coolant temperatures while the model mainly uses RPM. Occlusion is faithful to the served model and costs six extra forward passes. |
| 2026-11-21 | **Hugging Face Spaces instead of AWS EC2** | Free and simple: one Docker container with 16 GB RAM (enough for PyTorch and the NLI model), deployed from GitHub Actions. FastAPI serves the built React app, so no Caddy or second container is needed in production. Docker Compose with PostgreSQL stays for local use. |
| 2026-11-21 | **Groq `openai/gpt-oss-120b`** (reasoning effort low) | `llama-3.3-70b-versatile` was retired. gpt-oss-120b is the strongest general model on Groq's free tier. Its `【…】` citations are normalised to `[…]`. 429 rate limits are retried using the provider's wait time. |
| 2026-11-21 | **Corpus: three US government technical manuals + the glossary** (TM 9-8000, TM 9-2858, TM 10-570) | Public domain (17 U.S.C. § 105), so they can be indexed and redistributed. They're detailed on lubrication, cooling and fuel systems. Pages with heavy OCR noise are skipped, and line-break hyphenation is joined. |
| 2026-11-21 | **Relevance gate on the question alone** before adding prediction context to the query | Otherwise an off-topic question ("capital of France?") plus "low oil pressure" context still retrieved oil passages and produced a confident, irrelevant answer. |
| 2026-11-21 | **Guardrail: NLI (deberta-v3-small) over 1–3 sentence windows; supported = entailed ≥ 0.5, OR near-verbatim quote, OR ≥ 60% word overlap with no contradiction; advice sentences excluded; answers with < 50% supported claims are trimmed to the supported sentences, and fully unsupported answers are refused** | Scoring a claim against whole 800-character chunks gave ~0 entailment even for exact paraphrases (all three model sizes tested). On a hand-made set, sentence windows plus the paraphrase rule passed 4/4 grounded claims and rejected 4/5 fabricated ones; the miss is an NLI false entailment. The prediction itself is also passed as a premise, so statements about the user's readings can be checked. |
| 2026-11-21 | **Extractive fallback when no LLM key is set** | The app (and CI) stays fully usable without a paid or free key, and it never generates unsupported text. |
| 2026-11-21 | **Chroma over FAISS** | Persists to disk with metadata (source, page) out of the box and has a first-class LangChain integration. FAISS needs a separate docstore for metadata. At this corpus size, speed doesn't matter. |
| 2026-11-21 | **React + FastAPI over Streamlit** | A REST API plus a typed SPA is what real deployments look like, and it shows both halves. Streamlit would have been faster to build. |
| 2026-11-21 | **Groq / Gemini via plain HTTP** behind an abstract `LLMClient` | Two small classes instead of two SDKs. Switching providers is a config change. |
| 2026-11-21 | **SQLite locally, PostgreSQL in Docker Compose / Neon** through the same SQLAlchemy models and Alembic migrations | Zero-setup development and tests, real database in production. `JSON().with_variant(JSONB)` gives JSONB on Postgres. |
| 2026-11-21 | **Python 3.12 in Docker** (plan said 3.11) | Matches the development machine, so pinned wheels are identical in both places. |
